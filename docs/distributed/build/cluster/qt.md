# Qt based Cluster

This route builds `agl-instrument-cluster-standalone-demo`, a dedicated Instrument Cluster image with the Qt `cluster-refgui` application and `cluster-service`. The image uses a small userland and direct Qt EGLFS rendering. For the IVI-derived VSS/KUKSA dashboard image, use `agl-cluster-demo-qt` from the [image catalog](../common/reference/images.md#agl-cluster-demo-qt).

## Initialize the build

Complete [Common part](../common.md), including the selected board's host and BSP requirements. `AGL_SOURCE` is the checked-out source directory defined by [Download AGL source](../common/download-source.md). Use a separate build directory for this profile.

The following example targets a Raspberry Pi 4:

```sh
cd "$AGL_SOURCE"
source meta-agl/scripts/aglsetup.sh -m raspberrypi4 \
    -b build-qt-cluster-rpi4 agl-demo agl-ic
bitbake agl-instrument-cluster-standalone-demo
```

For a Raspberry Pi 5, initialize a new build shell with `-m raspberrypi5 -b build-qt-cluster-rpi5`. The other current hardware profiles include `sparrow-hawk` and `nanopc-t6`; use their corresponding machine name and a separate build directory after following the [Sparrow Hawk guide](../common/hardware/sparrow-hawk.md) or [Rockchip board guide](../common/hardware/rockchip.md).

The [`agl-demo` feature](https://git.automotivelinux.org/AGL/meta-agl-demo/tree/templates/feature/agl-demo/50_bblayers.conf.inc) adds `meta-agl-demo-shared` and the Qt layer, making the standalone recipe available. The [`agl-ic` feature](https://git.automotivelinux.org/AGL/meta-agl/tree/templates/feature/agl-ic/50_bblayers.conf.inc) supplies the Instrument Cluster layer. The [image recipe](https://git.automotivelinux.org/AGL/meta-agl-demo/tree/meta-agl-demo-shared/recipes-platform/images/agl-instrument-cluster-standalone-demo.bb) selects `packagegroup-agl-ic-core` when `agl-ic` is enabled; this installs `cluster-service` and enables the GUI's cluster backend. This standalone procedure uses those two features directly.

## Deploy the image

In the initialized build directory, find the output for your actual machine:

```sh
ls tmp/deploy/images/*/agl-instrument-cluster-standalone-demo*.wic*
```

For the Pi 4, the machine used in output names is `raspberrypi4-64`; for the Pi 5, it is `raspberrypi5`. Current hardware builds produce a `.wic.zst` image and matching `.wic.bmap` under `tmp/deploy/images/<machine>/`. Use that image in the selected board's deployment procedure; do not substitute the IVI image filename used in a generic example. For Raspberry Pi, follow [Raspberry Pi build and deployment](../common/hardware/raspberry-pi.md), decompress the `.wic.zst`, write the resulting `.wic` to the board's boot medium, and boot with a supported HDMI display attached. Use the serial console to observe startup.

## Check the running demo

The [cluster-refgui recipe and unit](https://git.automotivelinux.org/AGL/meta-agl-demo/tree/meta-agl-demo-shared/recipes-demo/cluster-refgui) install `/opt/apps/cluster`, `cluster.service`, and `/etc/default/cluster`. The unit starts the GUI automatically; the default environment selects `QT_QPA_PLATFORM=eglfs`. It renders directly to the board's graphics device, so the standalone display does not need an IVI homescreen.

On the target console, run:

```sh
systemctl status cluster-service.service cluster.service
journalctl -b -u cluster-service.service -u cluster.service
cat /etc/default/cluster
```

The reference GUI should show the instrument gauges and the demo vehicle signals generated by `cluster-service`. If the GUI does not start, check the EGLFS and graphics-driver messages in the journal and confirm that the board's display is connected. Review [Instrument Cluster reference GUI (Qt)](../../../components/applications/cluster-dashboard.md) and [Instrument Cluster service](../../../components/services/cluster/cluster-service.md) before changing from demo input to CAN input.

For an integrated cluster and IVI on one board, follow the separate [Container integration build guide](../../../small-integrated/containers/build-guide.md). Its `agl-ic-container` feature configures container multiconfig and DRM leases; its host-image deployment and display allocation belong to that integration procedure.
