# Build and boot on x86

Build a `qemux86-64` IVI demo, then run it in QEMU or VirtualBox. The partitioned WIC image can also be evaluated on a UEFI x86-64 PC, subject to that machine's drivers and peripherals. A successful emulator build does not guarantee compatibility with every PC.

For an evaluation without a source build, use the [QEMU x86-64 quickstart](../../../../quick-start/prebuilt/qemu-x86-64/index.md).

## 1. Initialize the build environment

Complete [host preparation](../prepare-host.md) and [source download](../download-source.md). These steps define `AGL_TOP` as the parent workspace and `AGL_SOURCE` as the selected source checkout.

From the source checkout, initialize a separate build directory:

```sh
cd "$AGL_SOURCE"
source meta-agl/scripts/aglsetup.sh -m qemux86-64 -b qemux86-64 agl-demo agl-devel
```

`agl-demo` enables the layers required by the Flutter and Qt IVI demo recipes. `agl-devel` enables development facilities; select features appropriate to your deployment. Use `-f` only when intentionally replacing an existing build configuration.

To share downloads and build cache with other builds, add these settings to `conf/site.conf` in the initialized build directory:

```bitbake
DL_DIR = "${HOME}/downloads"
SSTATE_DIR = "${HOME}/AGL/sstate-cache"
```

Adapt the absolute cache locations if your workspace is elsewhere. See [build initialization](../initialize-build.md) for features and configuration details.

## 2. Build an IVI image

Choose one target:

```sh
bitbake agl-ivi-demo-flutter
```

For the Qt IVI demo instead:

```sh
bitbake agl-ivi-demo-qt
```

The initial build can take several hours. Check the [host requirements](../prepare-host.md) for resource planning.

Inspect the output in `tmp/deploy/images/qemux86-64`. The [official master artifacts]({{ agl_download_base }}/latest/qemux86-64/deploy/images/qemux86-64/) use these filename forms:

| Purpose | Flutter image | Qt image |
| --- | --- | --- |
| Direct kernel boot | `agl-ivi-demo-flutter-qemux86-64.ext4.xz` | `agl-ivi-demo-qt-qemux86-64.ext4.xz` |
| UEFI disk / USB media | `agl-ivi-demo-flutter-qemux86-64.wic.zst` | `agl-ivi-demo-qt-qemux86-64.wic.zst` |
| VirtualBox disk | `agl-ivi-demo-flutter-qemux86-64.wic.vmdk.zst` | `agl-ivi-demo-qt-qemux86-64.wic.vmdk.zst` |
| Yocto QEMU configuration | `agl-ivi-demo-flutter-qemux86-64.qemuboot.conf` | `agl-ivi-demo-qt-qemux86-64.qemuboot.conf` |

Use the actual files generated by your chosen checkout and configuration. Timestamped files and their stable symlinks identify the same build. Do not pass a compressed `.xz` or `.zst` file as a virtual disk.

For Instrument Cluster or integrated system images, use the [Instrument Cluster build guides](../../../extra/reference/cluster/index.md), [Container integration build guide](../../../../../../small-integrated/container-integration/reference/build-guide.md), or [KVM build guide](../../../../../../small-integrated/kvm/build/index.md). Those profiles have their own MACHINE and feature requirements.

## 3. Run with QEMU

### 3.1 Use the Yocto wrapper after a source build

In a new shell, restore the build environment:

```sh
source "$AGL_SOURCE/qemux86-64/agl-init-build-env"
runqemu tmp/deploy/images/qemux86-64/agl-ivi-demo-flutter-qemux86-64.qemuboot.conf kvm serialstdio slirp
```

Substitute the Qt `.qemuboot.conf` filename if you built the Qt image. `runqemu` reads the generated configuration to select the kernel and root filesystem. Its graphical display and audio support depend on the host QEMU build; inspect `runqemu --help` for additional options.

### 3.2 Run an extracted WIC disk outside the build environment

Install the host's QEMU system emulator, OVMF firmware, and Zstandard tools. For Debian or Ubuntu:

```sh
sudo apt install qemu-system-x86 ovmf zstd
```

Locate a non-Secure-Boot OVMF firmware file supplied by your host package, for example `/usr/share/OVMF/OVMF_CODE.fd` or `/usr/share/OVMF/OVMF_CODE_4M.fd`. Other distributions install it in different locations. Set `OVMF_PATH` to a file that exists on your host.

The following example uses the Flutter WIC disk:

```sh
cd "$AGL_SOURCE/qemux86-64/tmp/deploy/images/qemux86-64"
IMAGE=agl-ivi-demo-flutter-qemux86-64.wic.zst
zstd -dk "$IMAGE"
DISK=${IMAGE%.zst}
OVMF_PATH=/usr/share/OVMF/OVMF_CODE_4M.fd  # replace with an installed firmware file

test -f "$DISK" && test -f "$OVMF_PATH"
qemu-system-x86_64 \
  -machine q35 -enable-kvm -cpu host -m 2048 \
  -bios "$OVMF_PATH" \
  -drive file="$DISK",if=virtio,format=raw \
  -device virtio-net-pci,netdev=net0 \
  -netdev user,id=net0,hostfwd=tcp:127.0.0.1:2222-:22 \
  -device qemu-xhci -device usb-tablet -device virtio-rng-pci \
  -vga virtio -serial mon:stdio \
  -audiodev pa,id=audio0 -device ich9-intel-hda -device hda-duplex,audiodev=audio0
```

Check that both files exist before launching QEMU. Replace the image name with the Qt WIC filename to run Qt. This boots the disk's UEFI bootloader; a separate `-kernel` option is unnecessary. The [quickstart](../../../../quick-start/prebuilt/qemu-x86-64/index.md#start-agl) describes host audio and KVM alternatives, SSH forwarding, and shutdown. QEMU [removed `-soundhw` in 7.1](https://www.qemu.org/docs/master/about/removed-features.html#creating-sound-card-devices-using-soundhw-removed-in-7-1); these examples use explicit audio devices.

## 4. Run with VirtualBox

Install [VirtualBox](https://www.virtualbox.org/wiki/Downloads), then decompress the matching VMDK image:

```sh
cd "$AGL_SOURCE/qemux86-64/tmp/deploy/images/qemux86-64"
zstd -dk agl-ivi-demo-flutter-qemux86-64.wic.vmdk.zst
```

Create a 64-bit Linux VM with at least 2048 MiB RAM. Enable EFI in its system settings, and attach the extracted `agl-ivi-demo-flutter-qemux86-64.wic.vmdk` as an existing hard disk on a SATA controller. Use the extracted Qt VMDK if you built Qt. The compressed `.zst` file is an archive and cannot be attached as the VM disk.

Start the VM and check the boot console and UI. VirtualBox graphics differ from QEMU's virtio GPU; verify the selected image's graphics driver and compositor configuration if the GUI fails to start. See [Troubleshooting](../../../../../../../troubleshooting/index.md) for log collection.

## 5. Evaluate on an x86-64 PC

Use a PC with UEFI boot enabled and a USB device large enough for the WIC disk. Run these commands on the build host to identify the USB device:

```sh
lsblk
```

Unmount its mounted partitions. Confirm the whole device path every time before writing; this replaces the selected device's contents. Set `USB_DEVICE` to the verified removable device, then write the decompressed WIC stream:

```sh
cd "$AGL_SOURCE/qemux86-64/tmp/deploy/images/qemux86-64"
USB_DEVICE=/dev/sdX  # replace after checking lsblk
zstd -dc agl-ivi-demo-flutter-qemux86-64.wic.zst | sudo dd of="$USB_DEVICE" bs=4M conv=fsync status=progress
sync
```

Boot the PC from that USB device. Confirm kernel boot, storage, networking, and display operation for the particular hardware. For a PC requiring a different BSP or driver set, select an appropriate MACHINE and image configuration rather than assuming the emulator image covers it.
