# Contribution gide

You can participate in AGL through code, documentation, and bug reports. Choose the guide that matches the contribution you want to make.

## Propose a code change

Read the [general contribution guidelines](general-guidelines.md) for the development environment, accounts, and the Gerrit change and review workflow.

Identify the version your change targets and use the [contribution checklist](checklist.md) to complete the required checks.

## Improve the documentation

Use [Contribute to the documentation](documentation.md) to edit this GitHub Pages site, preview it with MkDocs and Material, run the structure and link validators, and submit a pull request. For changes intended for the original AGL documentation, follow the [upstream Gerrit workflow](documentation.md#contribute-to-the-original-agl-documentation).

When improving a procedure, include its version and environment, prerequisites, a way to check the result, and a link to the next task. These details help readers complete their work.

## Ask a question or report a bug

- For usage or development questions: [Getting help](../troubleshooting/getting-help.md).
- For reproducible defects: [Reporting bugs](../troubleshooting/reporting-bugs.md).
- For information to collect before reporting: [Gather context](../troubleshooting/index.md#gather-context) and [Diagnose common problems](../troubleshooting/diagnostics.md).

## Related information

Depending on your task, refer to [Distributed system](../distributed/index.md), [API & configuration](../components/index.md), and [Releases & migration](../releases/index.md).
